# Access Calculation Specification

## Purpose

Модуль `calculateAccess` из `src/domain/access.ts` определяет, есть ли у пользователя доступ к сервису, и перечисляет все источники этого доступа: прямые разрешения пользователя и разрешения его групп. Расчёт чистый: конфигурацию не меняет, системные часы не читает, момент расчёта получает параметром.

## Requirements

### Requirement: Расчёт возвращает решение и все источники доступа

`calculateAccess` SHALL возвращать объект `{ granted, sources }` для пары «пользователь — сервис»: `granted` показывает наличие доступа, а `sources` перечисляет все сработавшие разрешения. Переданную конфигурацию функция MUST NOT изменять.

#### Scenario: Доступ по прямому разрешению

- **WHEN** пользователю `boris` прямо выдано разрешение `p1` на сервис `ledger`
- **THEN** результат содержит `granted: true` и `sources: [{ kind: "direct", permissionId: "p1" }]`

#### Scenario: Доступа без разрешений нет

- **WHEN** у пользователя `vera` нет разрешений на сервис `ledger`
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Прямое разрешение пользователя учитывается

Разрешение SHALL считаться прямым источником, если его субъект — пользователь с идентификатором запрошенного пользователя, а `serviceId` совпадает с запрошенным сервисом.

#### Scenario: Прямое разрешение даёт доступ

- **WHEN** в конфигурации есть разрешение `{ subject: { type: "user", id: "boris" }, serviceId: "ledger" }`
- **THEN** расчёт для `boris`/`ledger` возвращает источник `{ kind: "direct", permissionId: "p1" }`

### Requirement: Разрешение группы учитывается по членству пользователя

Разрешение SHALL считаться групповым источником, если его субъект — группа, идентификатор которой есть в `groupIds` пользователя, а `serviceId` совпадает с запрошенным. Членство SHALL определяться только полем `groupIds` записи пользователя.

#### Scenario: Групповое разрешение даёт доступ

- **WHEN** `boris` входит в группу `support`, а у группы есть разрешение `p3` на сервис `mail`
- **THEN** расчёт для `boris`/`mail` возвращает источник `{ kind: "group", permissionId: "p3", groupId: "support" }`

#### Scenario: Чужая группа не даёт доступ

- **WHEN** `boris` не входит в группу `accounting`, которой выдано разрешение `p2` на `ledger`
- **THEN** в источниках доступа к `ledger` нет `p2`

### Requirement: Перечисляются все источники, прямые раньше групповых

`calculateAccess` SHALL включать в `sources` все подходящие разрешения и MUST сохранять порядок: сначала прямые источники, затем групповые; внутри каждой части — порядок разрешений в конфигурации.

#### Scenario: Прямой и групповой источники вместе

- **WHEN** у Анны есть прямое разрешение `p4` на `mail` и разрешение `p3` группы `support` на `mail`
- **THEN** `sources` равен `[{ kind: "direct", permissionId: "p4" }, { kind: "group", permissionId: "p3", groupId: "support" }]`

### Requirement: Разрешения других сервисов не учитываются

Расчёт SHALL учитывать только разрешения, у которых `serviceId` равен запрошенному сервису.

#### Scenario: Разрешение другого сервиса не даёт доступ

- **WHEN** у `boris` есть разрешение на `ledger`, а запрошен неизвестный сервис `unknown`
- **THEN** результат равен `{ granted: false, sources: [] }`

### Requirement: Момент расчёта передаётся параметром

`calculateAccess` SHALL принимать момент расчёта `at` в запросе и MUST NOT читать системные часы. При текущих правилах результат SHALL не зависеть от значения `at`.

#### Scenario: Результат не зависит от момента расчёта

- **WHEN** один и тот же запрос выполняется с `at` в 2020 году и с `at` в 2040 году
- **THEN** оба результата полностью совпадают

### Requirement: Пользователь без записи не получает групповой доступ

Если пользователя с запрошенным идентификатором нет в конфигурации, расчёт SHALL считать его членство в группах пустым.

#### Scenario: Неизвестный пользователь не получает доступ

- **WHEN** запрошен пользователь, которого нет в `users`, и для него нет прямых разрешений
- **THEN** результат равен `{ granted: false, sources: [] }`
